# 多用户管理功能需求草案 v0.2（本机多账号 · 岗位权限隔离）

**状态**：草案，待评审。**日期**：2026-11-01
**方向**：不再是"局域网多人同时在线"，而是**同一台电脑**上多账号按岗位分配题库权限，**防止误操作**。程序保持本机本地运行、不开放局域网访问。

---

## 1 目标与要解决的问题

用户的真实诉求：**担心有人误操作**，希望不同的人用本程序时，只能碰自己岗位的题库，不能改到别人的。

- 例如：**电气工程师登录后，只能操作"电气"分类的题库**，看不到/动不了暖通、消防、弱电、管理等分类。
- 本机本地运行，多账号只是"**这台电脑上**谁可以用、能用哪块"，**不开放局域网**，其它电脑无法访问。

**一句话定位**：把「一台机器上人人都是管理员、可以互相乱改」变成「每人一个账号、只在自己的岗位分类里操作」。

---

## 2 范围界定

### 2.1 做（最小闭环）

| 能力 | 说明 |
|------|------|
| 账号体系 | 管理员创建用户：用户名 + 密码，可启用/停用、重置密码 |
| 登录 | 启动后需登录；不登录进不去功能页 |
| 岗位授权 | 给每个用户分配权限到**某些一级分类**（如只"电气"） |
| 数据隔离 | 普通用户只能看到/操作其被授权分类下的题目，其余隐藏且接口层拒绝 |
| 角色 | 管理员（全量）+ 普通用户（仅授权分类）两类，够用不多做 |

### 2.2 明确不做

- **不做局域网/远程访问**：仍只 `127.0.0.1` 本机，程序不对外网开口（安全底线）。
- 不做精细化行级/按钮级权限（如只读不改），粒度到一级分类即可。
- 不做在线答题、阅卷、成绩。
- 不做复杂审计平台（可选留一个"谁改过什么"的简单记录，见 FR-MU-09）。
- 不做并发编辑协同（同一时间两人改同一题仍会冲突，用提示即可）。

## 3 功能需求

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-MU-01 | **用户管理**：管理员增/删/停用用户、重置密码；用户名唯一 | P0 |
| FR-MU-02 | **岗位授权**：创建/编辑用户时勾选其可操作的一级分类（可多选）；可有一个「全部分类」选项 | P0 |
| FR-MU-03 | **登录**：启动后先登录；失败给出原因 | P0 |
| FR-MU-04 | **会话**：登录态短期保持，提供「退出登录」 | P0 |
| FR-MU-05 | **分类可见性**：普通用户题库页只显示其被授权的分类，未授权分类不出现 | P0 |
| FR-MU-06 | **数据隔离执行**：未授权分类下的题目，增/改/删/导出在**接口层拒绝**（不只是界面隐藏），杜绝改 URL 绕过 | P0 |
| FR-MU-07 | **组卷范围**：普通用户组卷时只能从被授权分类选题；配额里未授权分类不可用 | P0 |
| FR-MU-08 | **管理员初始化**：首次启动强制创建管理员账号，未设置前功能不可用 | P0 |
| FR-MU-09 | **简单操作记录（可选）**：记录谁在何时对哪道题做了改动，设置页可查（不做成复杂平台） | P1 |
| FR-MU-10 | **管理员全量**：管理员账号不受分类限制，可见/操作全部 | P0 |

## 4 关键设计取舍

| 问题 | 建议 |
|------|------|
| 权限粒度 | 绑定到**一级分类**（电气/暖通/弱电/消防/管理），天然对应岗位，最直观；不做二级分类级细粒度 |
| 数据如何隔离 | 所有题目查询/写入在**后端按登录用户的可授权分类过滤**（`WHERE cat_id IN (…)`），界面隐藏只是第一层，**接口层二次把关**才防绕过 |
| 密码存储 | `hashlib.scrypt` 加盐哈希，绝不明文存库；密码框不回显 |
| 会话 | 会话 ID（`secrets` 随机）落本地 SQLite + 短期过期；零第三方依赖 |
| 新增数据表 | `user`、`user_category`（用户 × 分类授权）、`session`、可选 `audit_log` |
| 局域网 | **默认且仅** `127.0.0.1` 本机绑定，不提供打开局域网访问的选项（用户明确不要） |
| 迁移旧库 | 建表 + 首次强制建管理员；已有题库/试卷数据不动；老数据默认划归管理员全部可见 |

## 5 工作量与技术影响（粗估）

- 后端：`user`/`session`/授权表 + 登录/登出/用户管理/鉴权中间件；所有写题与组卷接口加分类过滤。
- 前端：登录页；用户管理页（建号 + 勾分类）；题库页按授权只显示本岗位分类。
- 测试：**权限隔离是用例重点**——未授权分类即使"造 URL 调接口"也必须被拒；预计新增 30–45 项，存量用例需补登录前置。
- 保持**零第三方依赖、纯标准库、单文件库**；`启动试卷系统.bat` 行为不变。

---

## 6 建议

1. 方向正确、解决真实的误操作痛点，**比"局域网多人在线"值得做**。
2. 权限按**一级分类**落，最直观、实施复杂度低；不用上二级分类/行级权限。
3. **接口层强制过滤**是必须的——界面隐藏挡不住懂点技术的人，防绕过要靠后端。
4. 先做 **FR-MU-01~08 + 10（P0 最小闭环）**；审计 FR-MU-09 可后置。
