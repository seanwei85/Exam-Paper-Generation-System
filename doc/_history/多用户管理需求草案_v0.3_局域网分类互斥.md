# 多用户管理功能需求草案 v0.3（局域网 + 多账号岗位授权 + 分类级互斥）

**状态**：草案，待评审。**日期**：2026-11-02
**方向**：允许**局域网**访问；多账号按**岗位（一级分类）**授权；**同一分类同时只允许 1 人写操作**，从而多人同时登录、各写各的分类、互不干扰，也从根本上消除题目级写冲突。

---

## 1 目标

1. 不同工位的同事**都能登进来用**（局域网）。
2. 每人只有自己岗位分类的权限，**防误操作**（电气工程师只碰"电气"）。
3. **多人可同时在线、同时工作但不相互干扰**：靠"同一分类同时只有 1 人可写"保证，大家永不写同一道题。

---

## 2 核心机制：分类级互斥（本方案的关键）

- 写操作（新增/修改/删除题目、导入、删草稿、组卷会改动配置的操作）发生在某个**一级分类**上。
- 读写分离：
  - **读**：多设备可并读，不限。
  - **写**：**同一时刻，同一分类只允许 1 个登录会话在写**。登录或首次写入某分类时占用该分类，他人再写同分类会被阻断。
- 效果：电气工程师在线编辑"电气"时，管理员可在另一台电脑同时编辑"暖通/消防"——只有**同分类**才互相顶掉。不同分类、多人并行，永不写同一题。

| 互斥维度 | 覆盖 | 复杂度 |
|---|---|---|
| 全局 1 人 | 所有人互斥 | 低 |
| **分类级（本方案）** | 同分类互斥，跨分类并行 | **低~中** |
| 题目级 | 同题互斥 | 中高（并发乐观锁） |

选用"分类级"：与岗位授权天然贴合，成本几乎等于全局互斥，却保留多人在线并行。

---

## 3 范围界定

### 3.1 做

| 能力 | 说明 |
|------|------|
| 局域网访问 | 可配置绑定 `0.0.0.0`，其它工位设备可开。**默认仍 127.0.0.1 本机**，局域网需主动开启 |
| 多账号 + 登录 + 会话 | 管理员建用户、登录、短会话、退出 |
| 岗位授权 | 每人授权到若干一级分类；管理员全量 |
| 分类级互斥写 | 同分类同时仅 1 会话可写，跨分类并行 |
| 接口层隔离 | 未授权分类在接口层拒绝（不只界面隐藏） |

### 3.2 不做

- 不做题目级并发合并/乐观锁（已被分类级互斥替代）。
- 不做精细按钮级/行级权限，粒度到一级分类。
- 不做复杂审计平台，可选留简单"写痕迹"（见 FR-MU-09）。
- 不做真正 HTTPS；局域网内 HTTP 明文，接受防护等级（见 §5 安全）。
- 不做云/远程互联网访问。

## 4 功能需求

| 编号 | 需求 | 优先级 |
|------|------|--------|
| FR-MU-01 | 用户管理：管理员增/删/停用用户、重置密码；用户名唯一 | P0 |
| FR-MU-02 | 岗位授权：创建/编辑用户时勾选可操作的一级分类（可多选）；提供「全部分类」 | P0 |

| FR-MU-05 | 数据隔离执行：未授权分类的增/改/删/导出在**接口层拒绝** | P0 |
| FR-MU-06 | 组卷范围：普通用户组卷只能从被授权分类选题；配额中未授权分类不可用 | P0 |
| FR-MU-07 | **分类级互斥写**：同一分类同时仅 1 会话可写；其它会话写同分类被明确提示并阻断 | P0 |

| FR-MU-11 | 管理员全量：管理员不受分类互斥外的限制，可见/操作全部 | P0 |

## 5 安全与运维（局域网带来的成本，必须接受）

| 项 | 说明 |
|----|------|
| 暴露面 | 同网段任何设备都能打开**登录页**。登录是第一道安全关，无法回避 |
| 密码传输 | HTTP 明文传输，可被同网段嗅探。本场景（内网、可信环境）可接受；若介意需上 HTTPS（证书会带来维护成本） |
| 绑定默认关闭 | 默认 127.0.0.1；只有主动开启才绑 0.0.0.0，开启时界面给醒目警示 |
| 防火墙 | 开局域网需放行端口；不同网段设置防火墙时可能有差异 |
| 会话 | 会话短期过期 + SameSite/Origin 校验，防 CSRF/越权 |
| IP 变化 | 局域网 IP 变化时访问地址变，需告知绑定机器的当前 IP |

## 6 工作量与技术影响

- 服务器进程序：绑定从 `127.0.0.1` 改可配置（`--host` / 设置项），局域网开 `0.0.0.0`。
- 后端新增：`user`、`session`、`user_category`（授权）、写占用表（分类→会话）；登录/登出/用户管理/鉴权中间件；写入口加分类占用校验。
- 前端新增：登录页、用户管理页（建号 + 勾分类）、（可选）写占用提示；题库页按授权只显示本岗位分类。
- 测试：权限隔离 + 互斥写是重点（未授权 URL 必须被拒、同分类第二会话写必须被阻、跨分类并行必须通过）；预计新增 35~55 项，存量用例补登录前置。
- 保持**零第三方依赖、纯标准库、单文件库**；`启动试卷系统.bat` 路由不变（默认本机）。

**互斥实现的简单性**：一张 `{分类 → 占用会话}` 内存表 + 登录/写入口查询即可；会话过期/退出时释放。不需要跨进程锁或分布式协调（单进程单机服务）。

## 7 与其他方案对比（结论）

| 方案 | 多人在线 | 写不冲突 | 成本 |
|---|---|---|---|
| 本机多账号（v0.2） | 否 | 天然 | 低 |
| 全局限 1 人 | 否 | 是 | 低 |
| 局域网全并发 | 是 | 否（需题目级锁） | 中高 |
| **局域网 + 分类级互斥（本方案）** | **是** | **是（跨分类并行）** | **低~中，最优** |

**结论**：本方案是"真要多人同时在线、又不互相干扰"里的**性价比最优解**，比全并发省掉题目级写锁的大头成本。
