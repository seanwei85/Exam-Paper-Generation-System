# 机房运维试题库与自动组卷系统 开发计划

**版本**：V1.2
**日期**：2026-10-25
**依据**：产品需求文档 V1.8
**目标**：交付一个双击即用的本机程序，数据存本机 SQLite 文件，离线可用

---

## 1 技术方案定稿

| 项 | 选定 | 原因 |
|----|------|------|
| 界面 | 原生 HTML + CSS + JavaScript 单页（无框架） | 无需联网加载依赖，体积小，打印样式可控 |
| 服务 | Python 标准库 `http.server` | 本机无 pip 网络，只能用标准库；单进程足够 |
| 数据 | SQLite（`sqlite3` 标准库） | 10 万题无压力，单文件可复制，事务可靠 |
| 导入解析 | Python 标准库自研（`zipfile` + `xml` 解 docx/xlsx，`zlib` 解 PDF 流） | 不依赖第三方库 |
| 启动 | `启动试卷系统.bat` → `pythonw server.py` → 自动打开浏览器 | 双击即用，无黑窗 |

**约束**：本机无法联网安装第三方包，因此不引入 pdf.js、openpyxl、node 等依赖，全部用标准库实现。PDF 解析为自研轻量实现，只处理文字型 PDF。

## 2 阶段划分与验收

### P0 骨架与数据层

**做**：目录结构、`server.py` 静态服务与路由框架、SQLite 建表、初始化五大类与二级分类、每日自动备份、`启动试卷系统.bat`。

**交付物**：能双击启动，浏览器打开空白框架页，数据库文件已生成，含默认分类。

**验收**：删掉 `data/` 重新启动，自动重建库与分类；连续启动两次不报端口占用。

### P1 题库与单题录入

**做**：题库列表（筛选、分页、排序）、单题录入表单（五种题型动态切换、空数自动统计、建议分值、实时校验）、编辑、删除、批量操作、示例题库（约 40 题，覆盖五类五题型）。

**交付物**：可完成"录一题 → 出现在列表 → 改一题 → 删一题"闭环。

**验收**：五种题型各录 2 题全部成功；非法输入（单选给两个答案、多选只给一个、答案不在选项内）被拦截并提示具体原因。

### P2 电子题库识别导入

**做**：文件上传、四种格式解析（xlsx / docx / txt / 文字型 pdf）、题号切分与字段识别、识别结果预览编辑、确认入库、失败清单、Excel 模板下载。

**交付物**：导入一份 20~30 题的真实文档，识别后人工微调即可入库。

**验收**：自建 25 题混合文档（含单选/多选/判断/填空/问答），题型、难度、答案识别正确率 ≥ 90%；扫描件 PDF 给出明确提示不崩溃。

### P3 组卷引擎

**做**：组卷参数页、实时校验（题量够不够、积分可行区间）、难度积分分配到易/中/难、按题型抽题、缺口报告、试卷编号（ZJLab-YYYYMMDD-NNN）、随机种子、快照落库、逐题改分与一键配平。

**交付物**：能从零参数生成第一套完整试卷数据。

**验收**：默认 100 分模板连续生成 10 套，每套总分 100、题量 60、难度积分精确等于 40；人为把某类题删到不足，系统拒绝出卷并报出精确缺口。

### P4 试卷与答案卷输出

**做**：卷面渲染（单位、标题、编号、时间、总分、时长、密封线、考生信息栏、大题分组、题号连续、分值标注）、A4 打印样式与防跨页、答案卷、试卷库台账、重新打印、导出 Word。

**交付物**：可打印的 A4 试卷与配套答案卷。

**验收**：打印预览无题目与选项被拆页；页码正确；答案卷题号与试卷一一对应；重启程序后重新打开历史试卷内容不变。

### P5 设置与数据维护

**做**：分类维护、单位名称与编号前缀、默认时长、数据备份与恢复、数据库统计、打开数据目录。

**交付物**：用户可自行改分类与单位信息，可一键备份到 U 盘。

**验收**：备份后清空数据再从备份恢复，题目与试卷数量、内容完全一致。

### P6 整体测试与交付

**做**：按需求文档第 10 章 16 条验收项逐条自测；接口级自动化脚本；修复缺陷；写使用说明。

**交付物**：可交付版本 + 一页纸使用说明。

**验收**：16 条验收项全部通过，含"重启电脑数据不丢""积分误差为 0""编号唯一"。

## 4 主要风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 扫描版 PDF 无法提取文字 | 用户以为坏了 | 检测到无文字层时明确提示"扫描件需 OCR，请用 Word/Excel"，不静默失败 |
| .xls 旧格式（非 xlsx） | 打不开 | 提示另存为 .xlsx，界面写明支持格式 |
| 填空题空数不统一 | 总分偏离 100 | 生成后显示差额，一键配平；模板按平均 2 空估算 |
| 浏览器打印分页差异 | 题目被拆页 | 用 `break-inside: avoid` + 每题块级包裹；提供打印自检页 |
| 本机无 Python 环境 | 无法启动 | 交付前检测 `python`，缺失时给安装说明；或后续打包 exe |
| 数据目录被误删 | 数据丢失 | 每日自动备份 + 设置页显示数据路径 + 一键备份到外部目录 |

## 5 实施顺序

先跑通主干（P0 → P1 → P3 的最小版本 → P4），让"录几道题就能出一套卷"尽早可用；再补 P2 导入（工作量最大）与 P5 设置；最后 P6 全量验收。

理由：导入解析是最不确定的部分，放在主干验证之后，避免卡住整体可用性。

其中三条打印断言不看截图、直接读 PDF：用自研的最小 CDP 客户端驱动无头 Chrome 走 `Page.printToPDF`，再用自研的极简 PDF 文本抽取器（`tests/pdftext.py`，zlib 解流 + 解析 ToUnicode CMap）把每页文字取出来，断言"每一页都有『第 N 页 共 M 页』""没有侧栏与按钮文字""页数不多不少"。只用截图或 DOM 是测不出这些的——打印出来的 PDF 是另一套渲染结果。

其中 P4 的 4 个与 P2 的 6 个用例是端到端渲染测试：启动独立服务 + 无头浏览器抓真实 DOM，验证卷面编号、密封线、大题标题、填空空数标注、答案卷逐空答案、导入识别结果表等元素真实存在，不依赖人工看图。

另有 P2 的 11 个交互测试（`tests/test_p2_interact.py`）：用自研的最小 CDP 客户端（`tests/cdp.py`，纯标准库实现 WebSocket）驱动无头 Chrome **真点按钮、真改输入框**，断言"删掉一行后行数与勾选数同步、缺答案标黄、入库被拦下、失败原因页内列出、最终 6 题真的进库"。`--dump-dom` 只能拿静态 DOM，这类行为用它是测不出来的。

渲染断言统一剥离内联 `<script>` / `<style>` 后再做匹配。原因：页面模板字符串本身就含"识别结果""共 N 空"等字样，直接对整份 DOM 做字符串计数会把源码当成渲染结果，让断言假性通过。

### 6.1 实现过程中的关键缺陷与修复

| 缺陷 | 影响 | 修复方式 |
|------|------|----------|
| 难度分解未考虑各难度实际可用量 | 抽题中途凑不齐，出卷不足题量 | 难度 DP 加入可用量约束，改为按题型×难度求解 |
| 缺失难度键被当成"不限制" | 多选题没有易题却分配了易题，导致整类抽空 | 缺失键按 0 处理 |
| 必考锁定题难度余量为 0 时被跳过 | 锁定题没进卷 | 占用同题型其他难度的名额 |
| 数据目录参数在双模块下失效 | 指定数据目录后仍读写正式库 | 路径解析移到模块加载期 |
| 服务端口被占后连到旧实例 | 测试读到另一份数据 | 动态分配端口 + 校验数据目录 |
| 导入页 `?demo=1` 参数未被消费 | 解析成功后路由再次命中 demo，对解析接口形成循环请求，页面上"正在解析…"与结果表并存 | 进入示例分支时用 `replaceState` 摘掉参数，demo 只消费一次 |
| 识别结果表渲染在两个位置 | 勾选/改分类后页面出现两份表 | 结果表统一由 `#impStage` 容器承载，删除页面尾部那份 |
| FR-IM-09 模板下载未实现 | 用户没有"照格式填"的入口，导入成功率依赖自行摸索格式 | 新增 `importer.template_xlsx()` 与 `/api/import/template`，纯标准库生成 xlsx（五题型示例行） |
| FR-IM-02 按表头取列未实现 | 把表格行转纯文本再正则拆题，表头行会被当题干，"下载模板→填写→导回"这条路径是断的 | 抽取 `_xlsx_rows` 保留列位置，按列名映射字段（支持别名、列顺序任意、缺题型列可推断），无表头时才回退到文本模式 |
| 选项顺序按列位置排 | 列顺序打乱后选项变成 C/A/B，与标号语义不符 | 改为按 A~H 标号排序 |
| 分类下拉显示默认值但没写回数据 | 表格里看着是"电气"，提交时 cat_id 为空，后端报"未选择一级分类"，示例 6 题只入库 1 题 | 解析后统一 `impNormalize()` 把显示值写回；补充二级分类列并随一级联动 |
| 入库结果用 alert 弹窗 | 部分题失败时弹阻塞对话框，页面卡住，也无法自动化验证 | 改为表格上方内联清单，列出题干与具体原因，失败的题自动取消勾选，留在本页继续改 |
| 重复判定未考虑格式差异 | 从别处复制来的题「（　）」变成「( )」就判不出重复，等于判重形同虚设 | 比对前归一化：全角转半角、去空白、去括号占位与下划线；归一化后不足 6 字的不参与，防短语误判 |
| 极短题干互相误判 | 若不做长度下限，"机房温度"这类四字题干会彼此相似 | 设 `MIN_LEN=6`，并加长度比、字符集重合度两道粗筛 |
| 导入记录只存在内存里 | 重启即丢，等于没留档 | 落在 `import_log` 表；空提交不写，全部失败要写 |
| 打印时 `@page` 边距设成 0 | 侧栏、页头、按钮被印上试卷，页脚也没有落脚处 | 页边距交给 `@page`，页脚用 `@bottom-center` 的 `counter(page)/counter(pages)` 生成；界面元素统一 `display:none!important` |
| 判"末尾多一页空白"其实是抽取器的错 | 目录对象里含 `/Pages 2 0 R`，被当成一个页面对象 | 页面识别改为 `re.search(rb"/Type\s*/Page(?![A-Za-z])", body)`，抽取页数与 PDF 里 `/Type /Page` 计数对齐 |
| `/api/questions/export` 返回 500 | 路由顺序问题：被 `/api/questions/<id>` 前缀分支先吃掉，`int("export")` 抛异常 | 导出分支放在前缀分支之前 |
| 批量改一级分类不改二级 | 出现「电气 + 暖通某二级」这种库里不存在的组合 | 改 `cat_id` 时一并写入该分类下的第一个二级；改 `sub_id` 时反查 `cat_id` |
| 查询条件在列表与导出里各写一遍 | 两边筛选逻辑会慢慢跑偏，"导出的和看到的不一致" | 抽出 `_q_where(params)`，列表与导出共用同一份条件 |
| 查重塞在 `save_question` 里 | 核心写入函数变成"相似就拒绝"，导入入库、脚本补题、单元测试全被拦下 | 查重上移到接口层 `create_question`；`save_question` 只管校验与写库，导入入库不再被误伤 |
| 测试的导航序号写成了实例属性 | 每个用例都从 1 开始，第二个用例的 URL 与第一个完全相同，Chrome 只换 hash 不重载，断言打在上一份数据上 | 序号挪到类级 `_nav_seq`（`tests/renderbase.py` 的 `nav()`），并把 p2/p7/p8/p9 统一改成调用它 |
